# ドット絵 制作依頼書（Codex 向け）

作成: 2026-10-18（Claude）。オーナーの決定（同日）に基づく。
素材の置き場所・命名・台帳・採用の流れは [asset-management.md](asset-management.md) に従う。キャラの正本は [../world/characters.md](../world/characters.md)。

## 0. 目的と分担

ゲームの3か所をドット絵にする。設定資料の水彩イラストは今のまま残し、ドット絵はそれを参照して描き起こす。

| 工程 | 担当 |
|---|---|
| ドット絵の描き起こし（承認済みイラストを参照） | **Codex** |
| 採否の判断 | オーナー |
| 仕上げ（ドット格子へのスナップ、色数の検査、背景の透過、大きさ・足元の位置合わせ）とゲームへの組み込み | Claude（スクリプト） |

**イラストを縮小・減色しただけのものは不可。** 2026-10-18 に自動変換を試したところ、目や口がつぶれてモザイクにしか見えなかった。目を大きく、髪を数色のかたまりに、輪郭をはっきり、と描き直すこと。

## 1. 共通ルール

- **共通パレット**：最初に、全素材で使う共通パレット（32色まで）を1枚作る（`art/pixel/palette-v1.png`）。各素材はこの中から選ぶ
- **1素材の色数**：16色まで（透明は数えない）
- **輪郭**：外周に1ドットの濃い輪郭線。真っ黒ではなく、こげ茶など素材の色に合わせた濃い色にする
- **アンチエイリアスなし**：中間色でぼかさない。背景は透明、または純白（Claude が透過する）
- **向き**：ほぼ正面〜やや斜め。12名と主要キャラで向きをそろえる
- **出力サイズ**（2026-10-20 改定）：生成ツールが出した大きさのままでよい。**無加工のものを原本として登録**し、指定のドット数への変換（ドットの間隔の見積もり、1ドット1色への変換、共通パレットへの色寄せ、背景の透過）は Claude のスクリプトが行う
  - 理由: 画像生成AIは本物のドット格子を出力できない。2026-10-20 の試作5点は、1254×1254・1774×887 などの生成サイズで、ドットの境目のぼかしにより1万色を超えていた。これは描き手の問題ではなく、生成ツールの性質
  - そのうえで、ドットが大きくはっきり描かれ、1ドットの中が1色に近いほど、変換後の仕上がりがよい
- **アニメーション**：横一列のスプライトシート（左から1コマ目）。コマ同士で足元・体の位置がずれないこと
- **世界観**：中世ヨーロッパ風の港町マサリエ。電気や蒸気機関の機械は出さない

## 2. 依頼する素材

### A. 客の注文アイコン（12点）

| 項目 | 内容 |
|---|---|
| 大きさ | **48×48 ドット** |
| 範囲 | 顔と肩まで（バストアップ） |
| 参照 | `art/characters/customers/customers-a-v1.png`（1〜6）・`customers-b-v1.png`（7〜12）。並びは characters.md「新しい12名」の表と同じ |
| ファイル名 | `art/pixel/customers/<英字>-icon-v1.png`（例：`cerise-icon-v1.png`） |
| 表示 | ゲームでは直径42pxの丸い枠に入る。顔が中央に来ること。髪飾り・耳・帽子などの特徴は残す |

12名の英字：cerise / noix / fig / sage / olive / toma / beurre / peche / mint / melissa / aprico / cardamom

### B. 店先のちびキャラ

店先の場面（`ShopDiorama`）で、今はコードで描いた仮の人形が出ている。これを置き換える。

| 対象 | 大きさ（1コマ） | 動き | コマ数 |
|---|---|---|---|
| ミフィ（店先に立つ） | 48×64 | 待機（呼吸・しっぽ） | 2 |
| 客12名 | 48×64 | 待機（呼吸） | 各2 |

- 2頭身ほどのちびキャラ。12名は A のアイコンと同じ人物とわかる配色・特徴にする
- ファイル名：`art/pixel/chibi/<名前>-idle-v1.png`（例：`mify-idle-v1.png`、`cerise-idle-v1.png`）
- 入店・退店の歩きは今回は不要（第2段階で検討）

### C. ケーキ製造のアニメーション

製造中に3工程が順に表示される（0.75秒・0.75秒・0.9秒。`src/components/CraftResult.jsx`）。4コマなら1工程でほぼ1周する（1コマ約0.2秒）。工程の種類は9つで、全8レシピがこの組み合わせでできている（`src/game/craftPresentation.js`）。

| 工程（kind） | 使うレシピ数 | 場面 |
|---|---|---|
| whisk | 3 | ボウルで泡立て |
| oven | 7 | 薪窯で焼く |
| layer | 4 | スポンジにクリームと果物を重ねる |
| decorate | 3 | 絞り袋で飾る |
| glaze | 2 | 上から艶がけ |
| roll | 2 | めん棒で生地をのばす |
| fold | 1 | 生地を折りたたむ（ミルフィーユ） |
| steam | 1 | 湯せんで蒸す（プリン） |
| cool | 1 | 窓辺で冷ます |

| 項目 | 内容 |
|---|---|
| 大きさ（1コマ） | **128×96 ドット**（作業台とちびミフィが入る横長） |
| コマ数 | 各工程 **4コマのループ** |
| ファイル名 | `art/pixel/craft/craft-<kind>-v1.png`（例：`craft-whisk-v1.png`） |
| 内容 | ちびミフィ（B と同じ姿）が作業する。道具・台は工程ごとに違ってよいが、作業台の高さと床の位置はそろえる |
| 注意 | 工程の中のケーキは、レシピによって形が違う（丸・タルト・プリンなど）。**ケーキ本体は描かず、台の上を空けておく**。ケーキはゲーム側で重ねる。描くのは道具・手元・ミフィ・湯気や粉などの効果 |

## 3. 進め方

1. **試作（先に1回だけ）**：共通パレット、A のうち2名（cerise・sage）、B のミフィ、C の whisk。オーナーが方向性を確認する（2026-10-20 に方針承認）。候補は `art-inbox` ブランチの `inbox/<日付>/` に無加工で push する（[asset-management.md](asset-management.md)「候補の置き場所」）
2. 試作が通ったら残りを作る。A・B・C の順でよい
3. 各段階でオーナーの採用を受けてから原本登録する（`docs/art/asset-log.md` に1行ずつ、プロンプトは `docs/art/prompts/`）
4. **客の名前と絵は同時に切り替える**（オーナー決定）。A と B の客12名がそろうまで、ゲームの名前は変えない
5. 原本登録の後、Claude が `scripts/process_game_art.py` に仕上げ処理を足し、`public/images/` への出力とゲームの組み込みを1つのPRで行う

## 4. 受け入れの確認項目（Claude がスクリプトで検査する）

`scripts/check_pixel_art.py` で自動検査できる。**検査するのは、Claude のスクリプトで指定のドット数に変換した後の画像。** 生成ツールが出した無加工の原本は、サイズや色数で FAIL になって当然なので、原本には実行しない（2026-10-20 改定）。

```
python3 -m pip install pillow numpy
python3 scripts/check_pixel_art.py <変換後の画像> --kind icon                       # 採用前の候補を変換したもの
python3 scripts/check_pixel_art.py                                                  # art/pixel/ 以下すべて
```

種類（icon / chibi / craft / palette）は `art/pixel/` 以下のフォルダ名で決まる。採用前の候補は `--kind` で指定する。結果は1ファイル1行の PASS / FAIL と理由だけで、画像の中身は出力しない。

- 指定のドット数ちょうど（または均一な整数倍）
- 色数が16色以内で、共通パレットの色だけを使っている
- 半透明のドットがない
- アニメーションの各コマで、足元の行（いちばん下の不透明な行）が同じ
- 12名のアイコンで、顔の中心が枠の中央付近にある
