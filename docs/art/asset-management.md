# CAKING！ 画像素材の管理ルール

ゲームとアニメで共有するキャラ・背景の画像を、どこに・どう置くかの決まり。
新しい画像を採用・差し替えするときは、必ずこのルールに従う。

## 基本の考え方

- **採用した画像の原本は caking-game リポジトリに置く。** ゲームとアニメの共通の「正」になる。
- **ゲームが表示する画像は、原本から作った加工版。** 原本を直接いじらない。
- **ボツ案・候補はGitに入れない。** `art/_inbox/`（Gitの対象外）に置く。
- **すべての採用画像は台帳に記録する。** いつ、何で、どのプロンプトで作ったかを残す。
- **画像の生成から採用・pushまでは、画像を作ったエージェント（Codex）がリポジトリ内で行う。** 採用の判断だけは人が行う。

## 置き場所

```
caking-game/
├── art/                          ← 原本（ゲームには直接配信しない）
│   ├── _inbox/                   候補置き場（.gitignore に入れてコミットしない）
│   ├── characters/
│   │   └── mify/
│   │       ├── mify-ref-v1.png          3面図（キャラの基準）
│   │       ├── mify-expressions-v1.png  表情シート（原本のまま）
│   │       └── parts/                    切り出した目・口パーツ（スクリプトで自動生成）
│   ├── backgrounds/
│   ├── props/                    小物（ケーキ、鍵など）
│   └── branding/                 ロゴ、エンドカード
├── docs/art/
│   ├── asset-log.md              採用画像の台帳
│   └── prompts/                  生成に使ったプロンプト（画像1つにつき1ファイル）
└── public/images/                ← ゲーム表示用（art/ から縮小・透過処理して作る）
```

- アニメのリポジトリ（caking-anime）は、同期スクリプトで `art/` と `docs/world/` を取り込む。アニメ側で原本を直接編集しない。
- 背景除去や縮小などの加工は、手作業ではなくスクリプトで行い、`art/` から再生成できるようにする。

## ファイル名

`キャラ名-種類-v番号.png`（すべて半角小文字のローマ字）

| 項目 | 決まり |
|---|---|
| キャラ名 | mify / miru / anis / cumin / cinnamon / laurel / pepper |
| 種類 | ref（3面図）、expressions（表情シート）、pose-ポーズ名（例：pose-offer-cake） |
| 背景 | bg-場所-状態-v番号（例：bg-shop-before-v1、bg-harbor-window-v1） |
| 番号 | 描き直したら v2、v3 と上げる。**採用済みのファイルは上書きしない** |

古い版は消さずに残してよい。どの版を使うかは台帳の「状態」で管理する。

## 台帳（docs/art/asset-log.md）

採用した画像ごとに1行追加する。

| ファイル | 日付 | 生成元 | プロンプト | 状態 | メモ |
|---|---|---|---|---|---|
| art/characters/mify/mify-ref-v1.png | 2026-10-11 | ChatGPT 画像生成 | docs/art/prompts/mify-ref-v1.md | 採用 | 後ろ姿のリボン位置を要修正 |

- **生成元**：ChatGPT、Canva AI、自作など。外部の素材を使った場合は、出典と利用規約のURLも書く（音源の `audio-licenses.md` と同じ考え方）
- **状態**：候補 / 採用 / 廃止
- **プロンプト**：添付した参照画像（例：元の絵柄の漫画ページ、旧デザイン）も一緒に記録する

## 候補の置き場所

- 生成した候補は `art/_inbox/` に、日付付きの名前で保存する（例：`20261011-mify-ref-c3.png`）
- `art/_inbox/` は .gitignore に入れ、コミットしない
- 採用されなかった候補は、まとめて消すか、残したい場合は Google Drive の `CAKING素材/` に移す

## 作業の流れ（Codexで画像を作る場合）

1. **作業前**：`git pull` で最新を取り込む（Claude Code も同じリポジトリに push するため）
2. **生成**：候補を `art/_inbox/` に保存し、人に見せる
3. **採用**：人が採用する1枚と版番号を指示する。指示があるまで正式な場所には置かない
4. **登録**：採用画像を正式な名前で `art/` に置き、プロンプトを `docs/art/prompts/` に、1行を `docs/art/asset-log.md` に追加する
5. **push**：`art/` と `docs/art/` の変更だけをコミットして push する。コミットメッセージは「art: mify-ref-v1 を採用」の形にする
6. **ゲームへの反映は別作業**：`public/images/` の差し替えは、人から明示的に指示があったときだけ行う。`main` への push でゲームが自動公開されるため

Claude Code で作業する場合も同じ流れに従う。

## 注意

- 画像はファイルが大きく、今のゲーム画像だけで約24MBある。原本が増えてリポジトリが重くなってきたら、Git LFS（大きなファイルを別管理する仕組み）の導入を検討する
- 絵柄の基準は `mify-ref` の最新の採用版。他キャラの素材を作るときも、この絵を添付して絵柄をそろえる
