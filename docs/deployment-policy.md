# CAKING 公開・配布方針

決定日: 2026-08-08
最終確認: 2026-08-31

## 決定事項

CAKINGは、開発中のオンライン動作確認とスマートフォン実機確認にGitHub Pagesを使用する。

- `main` への反映をGitHub Actionsで自動ビルド・デプロイする。
- 公開URLは `https://anyhoe104-spec.github.io/caking-game/` を使用する。
- スマートフォンでは通常のブラウザ表示に加え、PWAとしてホーム画面へ追加した状態も確認する。
- ローカルサーバーの起動や同一LAN内からの接続は、デバッグが必要な場合に限って使用する。
- プレイヤー向けに広く公開する段階になったら、itch.ioへのHTML5版掲載を追加で検討する。

## この方針を採用する理由

現在のCAKINGはReactとViteで構築された、画面操作・状態管理中心のクライアントサイドゲームである。外部API、ログイン、決済、サーバー保存を使用しておらず、静的サイトとしてGitHub Pagesから配信できる。

GitHub Pagesを使用すると、複数PCのどちらから開発しても、`main` へ反映した最新版を同じURLから確認できる。スマートフォンでの確認時にも、PCで毎回ローカルサーバーを起動する必要がない。

## 現在の構成

- UI: React
- ビルド: Vite
- 配信: GitHub Pages
- 自動デプロイ: GitHub Actions
- セーブ: ブラウザの `localStorage`
- PWA: Web App ManifestとService Worker
- バックエンド: なし

この構成は、小規模な育成・経営・カード・放置系など、UI中心の個人開発ブラウザゲームに適している。リアルタイム物理演算や大規模な3D描画が必要になるまでは、専用ゲームエンジンへの移行を前提としない。

## Public化に関する確認結果

2026-08-08時点の確認では、リポジトリ内からAPIキー、パスワード、秘密鍵、認証トークンは検出されなかった。外部APIへの通信、Cookie、ログイン、決済、個人情報入力も実装されていない。本番依存パッケージの監査結果は脆弱性0件だった。

GitHub FreeではPrivateリポジトリのGitHub Pagesが利用できないため、2026-08-08にリポジトリをPublicへ変更し、GitHub Pagesを有効化した。

Public化すると、ソースコードだけでなく、コミット履歴、PR、Actionsログ、設計資料、画像素材も閲覧・複製可能になる。この点を了承した上で公開する。

### Public化は目的ではなく制約の帰結である（2026-08-31 補足）

この決定の順序を明確にしておく。CAKINGをPublicにしたのは、公開開発を志向したからではなく、
**無料でオンライン実機確認を行う手段がGitHub Pagesしかなく、そのPagesがPrivateリポジトリで
使えなかったため**である。したがって「オンラインで実機確認できること」という要件を別の手段で
満たせるなら、Publicである必然性はない。

2026-08-31時点で、収益化はまだ意思決定されていない。本書はitch.io掲載に触れているが、
無料配布か有料販売かは未定である。`docs/audio-sources.md` に「将来の商用化を想定する」という
記述があるのみで、方針としては確定していない。

## 公開前後の注意事項

- キャラクター名と画像が第三者の著作権・商標を侵害しないか継続して確認する。
- BGM・SEはライセンスを確認し、利用条件と出典を記録してから収録する。
- 生成画像についても生成元と公開利用の可否を記録する。
- 秘密情報をフロントエンドコードやGitHubリポジトリへ追加しない。
- セーブデータは端末・ブラウザごとの `localStorage` にあり、端末間では同期されないことを前提とする。
- Service Workerのキャッシュにより旧版が表示される場合があるため、更新確認では再読み込み、PWA再起動、サイトデータ削除を切り分けに使う。
- GitHub Pagesはログイン、決済、機密情報処理には使用しない。

## スマートフォンでの確認項目

- iPhone SafariとAndroid Chromeで主要画面が表示できる。
- 縦向きでボタンやボトムナビが画面外へ隠れない。
- 営業開始、注文、ケーキ作成、日報、翌日への遷移を操作できる。
- キャラクター、背景、レシピ画像が `/caking-game/` 配下から読み込まれる。
- ホーム画面へ追加してstandalone表示で起動できる。
- 更新後に新しいバージョンへ切り替わる。
- 一度オンラインで読み込んだ後、想定した範囲でオフライン表示できる。
- ブラウザデータ削除後に初期状態から正常に開始できる。

## 配信先の選択肢と、Privateへ移行する判断基準

### 収益化を見据えたときに実際に効いてくるリスク

Publicであることのリスクは「ソースコードを読まれること」だと捉えられがちだが、
CAKINGの規模では実害はそこではない。

| 資産 | 現状 | 収益化時のリスク |
|---|---|---|
| ソースコード | LICENSE未設定のため既定で無断利用は不可。法的には保護される | 低 |
| 画像素材 | 生成画像。生成元と公開利用可否の記録は本書の注意事項として未完了 | 中 |
| 音源 | 2026-08-31に全ファイルを自作の生成音源へ置き換え済み。権利はプロジェクトに帰属 | 現状なし |

**最も強く収益化と衝突するのは音源・素材のライセンス条項である。** 多くのAI音楽サービスと
素材サイトは「素材単体の再配布」を禁止しており、Publicリポジトリは `git clone` で音源ファイルを
単体取得できるため、これに該当する可能性がある。有料音源を導入した時点でこの制約が発生する。

裏を返すと、音源をすべて自作に切り替えた現在、**Publicのままでも権利上の問題は生じていない**。

### ホスティングの選択肢

| 方法 | Privateリポジトリ | 費用 | ブランチ別プレビュー | 商用利用 |
|---|---|---|---|---|
| GitHub Pages（現行） | 不可 | 無料 | なし | 可 |
| GitHub Pages + GitHub Pro | 可 | 有料 | なし | 可 |
| Cloudflare Pages | 可 | 無料枠 | あり | 可 |
| Netlify | 可 | 無料枠 | あり | 可 |
| Vercel | 可 | 無料枠 | あり | Hobbyプランは非商用のみ |

料金と規約は2026-08時点の調査値であり、採用前に各社の公式ページで再確認する。

移行先としてはCloudflare Pagesを第一候補とする。Privateリポジトリを無料枠で扱え、商用利用の
制限がなく、**ブランチごとにHTTPSのプレビューURLが自動生成される**ためである。
最後の点は開発フローに直接効く。現在はブランチの内容を実機で確認するために `main` へマージするか、
USB経由のポートフォワーディングを使う必要があるが、プレビューURLがあればブランチをpushするだけで
スマートフォンから開けるようになる。HTTPS配信のためService Workerも通常どおり動作する。

### Privateへ移行する判断基準

現時点では移行しない。次のいずれかを決定した時点で「Privateリポジトリ + Cloudflare Pages」へ
一括で移行する。

1. 有料のAI生成音源（Suno等）を導入すると決めたとき
2. itch.ioで有料販売すると決めたとき

このどちらかが確定するまではPublicを維持する。移行を前提とした技術的な準備は先行して完了させて
あるため（下記「配信先の切り替え」を参照）、決定時の移行コストは小さい。

### 収益化を決める際に併せて確定させる項目

1. リポジトリ全体のLICENSE（現在未設定）
2. リポジトリの公開範囲
3. 素材の権利方針とライセンス台帳（`docs/audio-licenses.md`）
4. 配布先と課金モデル（無料配布 / 投げ銭 / 有料販売）

## 配信先の切り替え

2026-08-31に、配信先へ依存していた設定をすべて排除した。**リポジトリの移行時にソースを書き換える
必要はない。**

| ファイル | 以前 | 現在 |
|---|---|---|
| `vite.config.js` | `base: '/caking-game/'` 固定 | ホストを自動判定し、`BASE_PATH` で上書き可能 |
| `public/manifest.json` | `/caking-game/` の絶対パス | manifest自身からの相対パス（`./`） |
| `public/sw.js` | `const BASE = "/caking-game"` | `self.location` から自身の配信位置を導出 |

`CF_PAGES` と `NETLIFY` は各プラットフォームが自動的に設定する環境変数のため、
**Cloudflare PagesとNetlifyはビルド設定なしでそのまま動作する**。

```bash
npm run build         # GitHub Pages 向け（/caking-game/）
npm run build:root    # ルート配信向け（/）
BASE_PATH=/foo/ npx vite build   # 任意のサブパス
```

`build:root` はWindowsのcmd.exeでも動くようNodeスクリプト（`scripts/build-root.mjs`）経由にしてある。

### Service Workerのプリキャッシュ

`vite.config.js` の `precacheManifest` プラグインが、ビルド後に `dist/sw.js` へ
ハッシュ付きのバンドル名を埋め込む。これがないと初回訪問時にオフライン起動できない。
バンドルはService Workerが制御を獲得する前に要求されるため、`fetch` ハンドラを通らず
キャッシュされないためである。

## 将来の配布方針

開発中はGitHub Pagesを正規の確認環境とする。

ゲームとして第三者へ紹介できる品質になった段階で、Viteのビルド結果をHTML5ゲームとしてitch.ioへ掲載する。itch.ioでは紹介文、スクリーンショット、タグ、更新履歴を整備し、モバイル対応を明示する。

ユーザーアカウント、端末間セーブ同期、ランキング、オンラインイベント、決済などが必要になった場合は、GitHub Pagesとは別にバックエンドとデータベースの導入を検討する。
