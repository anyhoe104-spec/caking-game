## 1. 残りも任せられるか

**残り全部が本人しかできない作業ではありません。** 実装・不具合修正・画像や音声の改善・課金連携コード・テスト・説明文や審査資料の下書きは、引き続きCodexに任せられます。前回は「この環境で未検証」と「代行できない」を一括してしまいました。

| 作業 | Codexが担当できること | 本人または協力者が担当すること |
|---|---|---|
| 実機確認 | テスト設計、接続済み端末のログ解析・自動操作、再現・修正 | 端末接続、USB許可、画面消灯・着信などの実操作、触り心地・音の評価 |
| Android/iOSビルド | SDKが使える環境でビルド・エラー修正・設定整備 | 最初の環境提供、アカウント認証・署名の許可 |
| 美術・演出・音声 | 描画・アニメーション・素材の制作/組込み/最適化 | 目指す見た目と音の最終採否、有料素材費の判断 |
| 課金 | StoreKit/Play Billing接続、バックエンド・権利管理・復元の実装とテスト | 商品・価格・販売名義の確定、契約・本人確認・税務/銀行情報入力 |
| ストア資料 | 説明文、スクリーンショット構成、実装に沿った申告案、審査対応修正 | 申告内容・権利・契約の確認、公開判断 |
| リリース | 検証済み候補の準備、権限と承認があればアップロード支援 | 最終公開の承認。審査結果はストア側が判断 |

このセッションの環境にはAndroid SDK、Xcode、接続された実端末がありません。これは現在の環境の制限です。SDKがあるPC上でCodexを使うか、ログと画面録画を渡せば続きを担当できます。アカウントのパスワード・署名鍵はチャットやGitに貼らず、所有者のPC/ストア管理画面で扱います。

## 2. 「実機」とは何を確認することか

実機とは、手元のAndroidスマートフォンやiPhoneでゲームを起動し、実際に遊んで確かめることです。PCのブラウザ検証では拾えない、端末の描画負荷、音声制限、アプリ切替・終了、タップ位置、画面端の切れを確認します。

| 確認方法 | わかること | これだけでは確認できないこと |
|---|---|---|
| スマホのブラウザ/PWA | 小画面の見やすさ、操作、ブラウザ保存、PWA復帰 | ネイティブアプリの署名・更新・実課金 |
| エミュレータ/Simulator | OS別の起動やレイアウト、再現テスト | 実端末の発熱・電池・スピーカー音・手触り |
| ネイティブ実機 | インストールしたアプリの起動、保存、中断、音、操作 | ストア経由の購入・更新は別途テスト配信が必要 |
| ストアのテスト配信 | 実際の配布・更新、テスト購入・復元 | 本番審査の合格保証 |

最初は手持ちのAndroid 1台で十分です。iOS公開前にはiPhoneでも確認します。iPad対応を出す場合はiPad評価も必要です。ブラウザ版とネイティブ版の保存場所は別で、自動引っ越し機能はありません。

**公開中のGitHub Pagesはmainの旧版です。PR #8の確認には以下のローカル起動かネイティブビルドを使ってください。**

## 3. 最初に行うこと（Androidから始める）

目安: 初回環境準備1〜2時間、最初の動作確認30〜45分。SDKダウンロードやビルドのトラブル対応時間は別です。公開日は未設定。

### 3-A. PCへ最新版を準備

新しい作業フォルダを使う場合:

```sh
git clone --branch codex/atelier-quality https://github.com/anyhoe104-spec/caking-game.git
cd caking-game
git status --short --branch
node --version
npm ci
npm run lint
npm test
npm run native:sync
```

Node.js 22.12以上が必要です。既存フォルダでは、変更を消さずに `git status` と開始スキルで状態を確認してから更新してください。`native:sync`はWebのルート配布ビルドを両OSにコピーします。通常の`npm run build`はGitHub Pages用です。

### 3-B. 先にブラウザで触る場合（任意）

PCとスマホを同じ信頼できるWi-Fiにつなぎます。

```sh
npm run dev -- --host 0.0.0.0
```

表示されるNetwork URLに `/caking-game/` を付け、スマホChromeで開きます。表示されたURLに既にパスがある場合は重複させません。接続できなければPCのファイアウォールと同一Wi-Fiを確認します。

これは触り心地を見るための開発サーバーです。Vite開発時はService Workerを登録しないため、この方法でPWAオフラインの合格判定はしません。PWA検証はHTTPSで配布した候補、または既存の`verify-offline.cjs`を使う開発者向け検証で行います。

### 3-C. Androidにアプリとして入れる

1. PCにAndroid Studioを用意。SDK ManagerでSDK Platform 36とPlatform-Tools、必要なBuild Toolsを入れます。Gradle JDKは21に設定します。
2. スマホの開発者向けオプションを有効にし、USBデバッグをオンにします。メニュー名は機種で異なります。
3. データ通信可能なUSBケーブルで接続し、スマホ側の「USBデバッグを許可」を承認します。
4. リポジトリ直下で `npm run native:android`。Android StudioでGradle Syncの完了を待ちます。
5. 上部で自分の端末を選択し、Run（再生ボタン）を押します。端末にCAKINGがインストール・起動すれば準備完了です。
6. 下の実機チェックを行い、機種/OS/コミットと結果を記録します。

端末が出ない場合は、ケーブル・接続許可・USBドライバを確認します。ビルド失敗時はBuild Outputの最初のエラーから保存し、Codexへ渡してください。エラーの数だけ設定を無作為に変える必要はありません。

補助コマンド（Platform-ToolsがPATHにある場合）:

```sh
adb devices
```

`unauthorized`ならスマホ側の許可を確認します。Android StudioのLogcatで対象アプリを選択すると、クラッシュ時のログを取り出せます。[Android公式: 端末接続](https://developer.android.com/studio/run/device)、[開発者オプション](https://developer.android.com/studio/debug/dev-options)。

### 3-D. iPhoneにアプリとして入れる

1. Macと対応するXcode、iPhone、接続ケーブルを用意します。Macがない場合はAndroid確認を先行し、iOS用のMacまたはビルド環境を別途用意します。
2. Macで3-Aを実行してから `npm run native:ios`。`ios/App/App.xcodeproj`を開きます。
3. XcodeでApple Accountを設定し、アプリのSigning & CapabilitiesでTeamとBundle Identifierを確認。現在の仮IDは `io.github.anyhoe104spec.caking` です。
4. iPhoneを接続し、求められたら「このコンピュータを信頼」とDeveloper Modeを設定します。
5. Run先にiPhoneを選び実行。署名エラーが出たら文面を保存してCodexへ渡します。自分の端末への開発実行と、App Store/TestFlight配布の契約・権限は別です。
6. Androidと同じチェックを行います。シミュレータ合格だけでiPhone実機を合格扱いしません。

[Apple公式: 実機への実行](https://developer.apple.com/documentation/xcode/running-your-app-on-simulated-or-physical-devices)、[Developer Mode](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device)。

## 4. 実機チェック表

未実施は「未実施」、失敗は「不合格」と記録します。最初の1台で見つかった問題を直してから端末を増やす進め方を推奨します。電池残量・省電力設定も記録してください。

| ID | 操作 | 合格条件・確認点 |
|---|---|---|
| D01 | 初回起動→オープニング→営業開始 | 真っ白/クラッシュなし。文字・画像・アイコンが表示される |
| D02 | 5タブを往復、下までスクロール | ボタンがヘッダー/下部ナビに隠れない。ノッチ・ホームバーに重ならない |
| D03 | お客様をタップ→製造 | 対象レシピへ進む。連打しても製造数・消費・報酬が二重にならない |
| D04 | 工程を見る→別の製造でスキップ | 工程が進み、結果を読んで閉じられる。スキップ後に工程が巻き戻らない |
| D05 | 営業残時間を記録→一時停止→30秒待つ | 残時間が減らず、再開ボタンで続行できる |
| D06 | 製造中にホームへ→30秒→アプリへ戻る | 中断中に時間・素材回復・演出が進まない。再開で復帰し、二重消費なし |
| D07 | 画面ロック/解除、可能なら着信後に復帰 | 音が裏で鳴り続けない。再開後のBGM・SEが重複しない |
| D08 | 営業途中にアプリ完全終了→再起動 | 営業残時間・所持金・所持パーツを保持し、再開待ちになる |
| D09 | 製造後に完全終了→再起動 | 確定済み材料・報酬が二重反映されない。製造演出自体は復元されなくてよい |
| D10 | 無料パーツ購入/装備→帯取り外し/定番復帰→再装備→再起動。有料パーツ試着 | 外しても購入履歴・通貨が変わらず、再装備できる。再起動後も装備が残る。有料試着で請求・有料所有権が発生しない |
| D11 | 音量・ミュート・軽減設定変更→再起動 | 設定保持。聞こえる/無音が設定に一致し、音割れや突然の大音量なし |
| D12 | 営業終了→日報→次の日 | 製造結果が日報に隠れず、次の日へ進める |
| D13 | ネイティブアプリを機内モードで起動・製造 | 同梱画像で遊べる。PWAはHTTPS候補の初回キャッシュ完了後に別途検証 |
| D14 | Androidの戻る、端末回転、文字サイズ変更 | 操作不能/画面崩れ/保存消失なし。iPhoneは縦、iPadは対応方向を確認 |
| D15 | 10分連続でプレイ、音楽と動きを見る | 繰り返し引っかからない、操作が取りこぼされない、異常な発熱なし |
| D16 | 解放後の全8レシピ、Lv10・所持金10万のエンディング→継続 | 全レシピ描画・エンディング継続後も製造可能。未到達なら未実施と記録 |
| D17 | テスト配信の旧候補→新候補へ更新 | 同じ署名・IDで上書き更新でき、進行・設定・パーツが残る |

D16を早く確認するためのテストセーブは、開発者が専用テスト環境で用意します。本番データを改ざんしたり、未到達のケースを通過扱いにしません。D08/D09/D17はバックアップや復元を保証する機能ではありません。アンインストールでローカル進行が消える可能性があり、更新試験ではアンインストールしないでください。

滑らかさの体感評価と「60fpsを測定した」は別です。体感不良なら画面録画と条件を提出し、開発者がAndroid Studio Profiler/Chromeの計測やXcode Instrumentsでフレーム時間を調べます。計測前は60fps達成済みと記載しません。

[実機記録テンプレート](device-test-record.md)を端末ごとにコピーし、上のIDごとに結果を記録します。最小限必要なのは機種・OS・コミット・操作手順・期待結果・実際の結果・画面録画です。

```text
開始スキルでCAKINGを再開してください。

操作: 製造開始→ホーム→30秒→復帰→再開
期待: 一時停止から続きへ。二重消費なし
実際: <症状>
添付: 画面録画、該当時刻のLogcatまたはXcodeログ
この不具合を再現・修正し、関連検証と引き継ぎまでお願いします。
```

Codexがログを分析→修正→候補作成→同じケースを端末で再確認、の順です。クラッシュ・保存消失・重複課金・進行不能は公開前に解消します。スクリーンショットやログに通知・氏名・認証情報が混ざらないよう、提出前に確認してください。

### 課金工程でCodexが実装・検証するもの

- 現在の有料候補は `caking.moonlight.v1` / `caking.harborcrown.v1`。最終IDは商品登録前に確定する。
- 継続利用する見た目パーツを対象とし、ストアの商品情報から名称・価格を表示する。
- 購入成功だけでなく、取消、保留、通信失敗、重複通知、アプリ終了後の再開を扱う。
- ストアの署名済み取引/購入トークンをサーバーで検証。処理を重複させず、ストア所定の完了/acknowledgementと権利付与を整合させる。
- 同じストアアカウントでの再インストール・別端末への復元、返金/取消後の権利更新を確認する。
- iOSとAndroidをまたぐ権利共有は別設計。採用するならアカウント紐付けと運用を決める。現状は対応済みとしない。
- 機内モードの既購入権利をどう扱うかを決め、ローカルセーブの有料ID書き換えで解除されないことを確認する。
- 実カードの決済ではなく、各ストアのSandbox/ライセンステストから確認する。

実装時には[Apple購入/復元](https://developer.apple.com/documentation/storekit/offering-completing-and-restoring-in-app-purchases)と[Google Billing](https://developer.android.com/google/play/billing/integrate)の最新仕様を再確認します。

### ストアへ進むときの順序

AndroidはAndroid Studioで署名したAABを用意し、Play Consoleのテストトラックへ登録して端末からインストールします。iOSはXcodeでArchiveした候補をApp Store Connectへ送り、TestFlightで確認します。秘密鍵はリポジトリに置きません。

販売名義、サポート窓口、プライバシー方針のURL、説明文、スクリーンショット、対象年齢、データ収集・広告・課金の申告を揃えます。課金サーバーや分析SDKを追加した場合は、その実装を含めて申告を見直します。未実装の課金や未測定の性能を掲載文で約束しません。

Google Playのアカウント種別・作成時期によって本番公開前のテスト条件が異なります。内部テスト合格だけで公開可能と判断せず、Consoleに表示された条件を確認します。[Google公式: テスト要件](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en)

## 工房のバックアップと復元

設定を開くと営業と食材回復が止まります。「バックアップを作る」→「全文をコピー」でメモなどに保管できます。コピーが使えない端末では、選択された全文を端末のコピー操作で保管します。文字の一部だけを保存しないでください。

復元先で設定→「バックアップから復元」を開き、全文を貼り付けるかJSON/テキストファイルを選びます。「復元内容を確認」で日数・レベル・所持金を確認し、「この内容で復元する」を押すと現在の進行を置き換えます。現在の工房も先にバックアップしてください。営業中のデータは一時停止状態で復元します。

自動保存失敗時も書き出しは可能です。復元先へ保存できない場合は現在の進行を置き換えません。ローカルの復旧用控えは直前の保存1件で、アンインストールやサイトデータ削除を越えて残るものではありません。有料購入の権利はバックアップから取得できません。

実機では、全文コピー/貼り付け、ファイル選択、復元のキャンセル、営業中の復元後の再開を追加確認してください。これらの実機確認は未実施です。
